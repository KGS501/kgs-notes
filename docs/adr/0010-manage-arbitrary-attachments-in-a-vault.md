# Manage arbitrary attachments in a KGS-owned vault

Each source will store Managed Attachments under a hidden `.kgs-notes-attachments/<note-id>/` vault using immutable storage names and relative Markdown references; editable human names remain link labels. The Nextcloud adapter uses Notes REST for note semantics and WebDAV for this binary lifecycle, journaling multi-resource operations for repair. A new binary must be uploaded and verified before its Markdown reference is published remotely; until then it is a Pending Attachment and the note remains Saved Locally. Attachment markup adapts to the source so Nextcloud receives its compatible form while the Local Source uses standard file links. Removing a reference retains its exclusively owned vault file for at least 30 days and a later successful cleanup removes it. Unexpected remote vault deletion or mutation preserves the note reference, marks it Needs Attention, and offers retry, relink, download, or reference removal. Links to files outside this ownership ledger are External File References: KGS Notes may render or cache them but never rename, move, or delete them. They are fetched on demand unless explicitly made Available Offline, and Portable Export reports rather than silently copies them. This avoids treating attached Markdown files as notes and prevents KGS from claiming arbitrary source files, at the cost of a KGS directory convention that other clients can read but do not manage.
